# IW03: Настройка планировщика задач (cron)

## Цель

Научиться настраивать планировщик задач (cron) для автоматизации выполнения скриптов.

## Подготовка

Задание основано на лабораторной работе №2. Скопируйте файлы из лабораторной работы №2 в новую директорию `lab03` для дальнейшей работы.

## Задание

В проекте `automation` создайте ветку `lab03`. Создайте директорию `lab03` и скопируйте туда файлы из лабораторной работы №2 (папка `lab02`).

В директории `lab03` создайте файл `cronjob`. В данном файле пропишите задачи cron, которые будут запускать скрипт `currency_exchange_rate.py`:

1. Ежедневно в 6:00 утра для получения курса MDL к EUR за предыдущий день.
2. Еженедельно в пятницу в 17:00 для получения курса MDL к USD за предыдущую неделю.

Создайте файл `Dockerfile` в директории `lab03`, на основе Ubuntu или официального Python образа, который будет:

1. Устанавливать необходимые зависимости для запуска скрипта (cron, Python и необходимые библиотеки).
2. Копировать скрипт `currency_exchange_rate.py`, файл `cronjob` и entrypoint скрипт в контейнер.
3. Настраивать cron для выполнения задач, указанных в файле `cronjob`.
4. Запускать cron в фоновом режиме при старте контейнера.
5. Записывать вывод cron задач в файл `/var/log/cron.log`.

Для упрощения работы с cron рекомендуется использовать entrypoint-скрипт, который будет настраивать и запускать cron. Пример такого скрипта приведен ниже:

```bash
#!/bin/sh

create_log_file() {
    echo "Creating log file..."
    touch /var/log/cron.log
    chmod 666 /var/log/cron.log
    echo "Log file created at /var/log/cron.log"
}

monitor_logs() {
    echo "=== Monitoring cron logs ==="
    tail -f /var/log/cron.log
}

run_cron() {
    echo "=== Starting cron daemon ==="
    exec cron -f
}

env > /etc/environment
create_log_file
monitor_logs &
run_cron
```

Создайте файл `docker-compose.yml` в директории `lab03`, который будет использовать созданный Dockerfile для сборки образа и запуска контейнера.

Создайте файл `readme.md` в директории `lab03`, в котором опишите:

1. Как собрать и запустить контейнер с cron.
2. Как проверить, что cron задачи выполняются и вывод записывается в файл `/var/log/cron.log`.
3. Описание структуры проекта и назначения каждого файла.

## Представление

Загрузите скрипт в репозиторий GitHub и предоставьте ссылку на него.

## Оценивание

Каждый критерий оценивается по пятиуровневой шкале: 0%, 25%, 50%, 75% или 100%.

| ID | Критерий | Вес `q_i` | Штраф `D_i` | 0% | 25% | 50% | 75% | 100% | Примечания |
| -- | -------- | --------- | ----------- | -- | --- | --- | --- | ---- | ---------- |
| **C1** | Задаёт расписание cron для обеих требуемых задач | 3 | 0 | Файл `cronjob` отсутствует или не содержит ни одной выполняемой записи | Обе записи есть, но ни одна не соответствует требуемому выражению, валютной паре или периоду | Ровно одна задача корректна полностью; во второй неверно выражение, пара или период | У обеих задач верное выражение и период, но есть отклонение в перенаправлении вывода или в одном аргументе скрипта | Присутствуют `0 6 * * *` (MDL→EUR, предыдущий день) и `0 17 * * 5` (MDL→USD, предыдущая неделя), аргументы соответствуют, вывод направлен в `/var/log/cron.log` | Сверять с двумя выражениями из раздела «Задание» |
| **C2** | Контейнеризует cron в собираемом `Dockerfile` | 3 | 0 | `Dockerfile` отсутствует или образ не собирается | Образ собирается и выполнены не более 2 из 5 требуемых пунктов | Образ собирается и выполнены 3 из 5 требуемых пунктов | Образ собирается и выполнены 4 из 5 требуемых пунктов | Образ собирается и выполнены все 5 пунктов: зависимости установлены, скрипт, `cronjob` и entrypoint скопированы, cron настроен на `cronjob`, cron запущен в фоне, вывод идёт в `/var/log/cron.log` | Считать пункты, выполнив `docker build` и прочитав `Dockerfile` |
| **C3** | Оркестрирует контейнер через Compose | 1 | 0 | `docker-compose.yml` отсутствует или некорректен, либо `docker compose up --build` завершается ошибкой | Compose-файл есть, но сборка падает или используется `Dockerfile` вне `lab03` | `docker compose up --build` собирает образ, но контейнер сразу завершается или cron не запускается | Контейнер собирается из `Dockerfile` в `lab03` и остаётся запущенным, но entrypoint или команда обходят cron | `docker compose up --build` собирает образ из `Dockerfile` в `lab03`, контейнер остаётся запущенным, cron работает в foreground-режиме | Проверять `docker compose ps` после запуска |
| **C4** | Подтверждает выполнение задач выводом в `/var/log/cron.log` | 2 | 0 | Подтверждений нет или в логе отсутствует вывод cron | Лог есть, но содержит только сообщения запуска, без вывода задач | В логе есть вывод только одной задачи либо только результат ручного запуска | В логе есть вывод обеих задач, но в одной записи нет отметки времени или полученного курса | В логе есть вывод обеих задач с отметками времени и полученными курсами валют | Временно изменённое расписание или ручной запуск допускаются для пятничной задачи |
| **C5** | Документирует сборку/запуск, проверку логов и структуру проекта в `readme.md` | 1 | 0 | `readme.md` отсутствует или не содержит ни одной из 3 требуемых частей | Присутствует 1 из 3 требуемых частей, команды не работают как описано | Присутствуют 2 из 3 требуемых частей | Присутствуют все 3 части, но команда или описание файла неточны | Присутствуют все 3 части, и каждая команда работает как описано: сборка и запуск, проверка вывода, структура проекта и назначение файлов | Выполнять описанные команды при проверке |

Определения:

- **Корректная задача (C1):** выражение `0 6 * * *` (ежедневно, MDL в EUR, за предыдущий день) или `0 17 * * 5` (еженедельно, MDL в USD, за предыдущую неделю); аргументы `currency_exchange_rate.py` соответствуют валютной паре и периоду; вывод направлен в `/var/log/cron.log`.
- **Пункты Dockerfile (C2):** пять пунктов из раздела «Задание» (установка зависимостей; копирование скрипта, `cronjob` и entrypoint-скрипта; настройка cron на выполнение `cronjob`; запуск cron в фоновом режиме при старте контейнера; запись вывода cron в `/var/log/cron.log`).
- **Подтверждение (C4):** фрагмент лога или скриншот. Временно изменённое расписание или ручной запуск допускаются, так как еженедельная задача выполняется только по пятницам.
- **Требуемые части readme (C5):** три пункта из раздела «Задание» (сборка и запуск; проверка вывода cron; структура проекта и назначение файлов).

Итоговая оценка в процентах:

`G = max(0, (Σ P_i * q_i) / (Σ q_i) - 20 * k - 100 * p)`

где `P_i` — оценка по критерию в процентах (0, 25, 50, 75 или 100), `Σ q_i = 10`, `k` — число дней просрочки, `p = 1` при подтверждённом плагиате (иначе `p = 0`).
